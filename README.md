# Корпоративный транспорт

Система управления корпоративным транспортом: приложение пассажира, приложение водителя и
административная панель с аналитикой загрузки маршрутов. Данные связаны в одну цепочку —
поездки пассажиров и отметки водителей формируют статистику, на основании которой
администратор принимает решения о маршрутах и транспорте.

Город тестовых данных — Худжанд. Интерфейс на русском языке.

## Быстрый старт

```bash
pnpm install
pnpm db:up
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Приложение откроется на http://localhost:3000. База поднимается в Docker на порту **5433**
(нестандартный порт выбран, чтобы не конфликтовать с локально установленным PostgreSQL).

### Демо-доступы

| Роль | Телефон | Пароль |
|------|---------|--------|
| Администратор | +992900000001 | admin123 |
| Водитель | +992900000101 | driver123 |
| Пассажир | +992910000001 | pass123 |

Сид создаёт 16 остановок, 3 линии в двух направлениях, 4 транспортных средства,
4 водителей, 108 пассажиров и две недели истории рейсов с отметками водителей —
этого достаточно, чтобы аналитика сразу показывала перегруженный и недозагруженный маршрут.

| Команда | Что делает |

## Структура

```
apps/web/            Next.js 16 (App Router), три зоны в одном приложении
  src/app/(passenger)  /app     — PWA пассажира, mobile-first
  src/app/(driver)     /driver  — PWA водителя, mobile-first
  src/app/(admin)      /admin   — панель администратора, desktop-first
  src/lib/             доступ к данным, авторизация, агрегация аналитики
packages/domain/     бизнес-логика без зависимости от фреймворков + тесты
packages/db/         схема Drizzle, миграции, сид
docs/01-analysis.md  согласованные требования, модель данных, решения по конфликтам
```

Бизнес-логика (поиск ближайшей остановки, расчёт времени прибытия, загрузка рейса,
статусы маршрутов, сигналы администратору) вынесена в `packages/domain` и покрыта тестами.
Это позволяет позже перенести её в отдельный backend или в нативные приложения без переписывания.

## Как считается загрузка

1. **Спрос** — число пассажиров, отметивших «поеду» на рейсе.
2. **Факт** — максимальное число людей в салоне по отметкам водителя на остановках.
3. **Загрузка рейса** = наибольшее из спроса и факта, делённое на вместимость назначенного транспорта.

Спрос может превышать вместимость — это и есть сигнал, что сотрудники не помещаются в транспорт.

Статусы маршрута (пороги настраиваются в разделе «Настройки»):

| Статус | Условие по умолчанию |
|--------|---------------------|
| Перегрузка | не менее 30% рейсов с загрузкой от 100%, либо средняя загрузка от 95% |
| Низкая загрузка | средняя загрузка ниже 40% |
| Норма | остальные случаи |

Система не изменяет маршруты автоматически. Она показывает данные и предлагает варианты;
решение принимает администратор.

## Время прибытия: три источника

Система выбирает самый точный из доступных источников:

1. **GPS** — пока телефон водителя передаёт координаты, положение проецируется на линию
   маршрута, и время считается по оставшемуся расстоянию и скорости.
2. **Отметки водителя** — если координат нет, время пересчитывается от фактической отметки
   «Прибыл» на предыдущей остановке.
3. **Расписание** — отправление плюс смещение остановки.

Клиент обновляет живые данные раз в 15 секунд и сразу при возврате на вкладку; в фоне
опрос не идёт, чтобы не расходовать батарею.

## GPS и мониторинг

Телефон водителя передаёт координаты каждые 15 секунд, **только пока рейс в пути**: отслеживание
начинается по кнопке «Начать рейс» и прекращается при его завершении.

Администратор видит раздел «Мониторинг»: транспорт на карте, состояние связи и сигналы:

| Сигнал | Когда возникает |
|--------|-----------------|
| Отклонение от маршрута | Несколько точек подряд дальше заданного расстояния от линии маршрута |
| Нет данных о транспорте | Рейс начат, но координаты не приходят дольше заданного времени |
| Рейс не начат | Время отправления прошло, а водитель не начал рейс |

Пороги настраиваются в разделе «Настройки».

## Push-уведомления

Приложение работает как PWA и умеет присылать уведомления, когда закрыто: подъезд транспорта
к вашей остановке, изменение маршрута, отмена рейса, сообщение администратора.

Пассажир и водитель включают их сами в профиле — браузер спрашивает разрешение только по нажатию
кнопки. Для работы нужны ключи VAPID в `apps/web/.env`:

```bash
node -e "console.log(require('web-push').generateVAPIDKeys())"
```

Без ключей приложение работает обычным образом, уведомления остаются только внутри приложения.
Push требует HTTPS; на `localhost` работает без сертификата.
